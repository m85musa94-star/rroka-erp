# دليل النشر — تشغيل النظام عبر رابط دائم

## النشر على Laravel Cloud (المنصة المختارة)

> أسماء القوائم أدناه مأخوذة من توثيق المنصة؛ قد تختلف صياغتها قليلًا في الواجهة.

### ١. إنشاء الحساب والتطبيق
1. أنشئ حسابًا في [Laravel Cloud](https://cloud.laravel.com) واربطه بحساب GitHub المالك للمستودع `m85musa94-star/rroka-erp`.
2. أنشئ تطبيقًا جديدًا من هذا المستودع:
   - **الفرع (Branch):** `claude/rroka-furniture-erp-tasit6` (أو `main` بعد دمج العمل فيه).
   - **المجلد الجذر (Root directory):** اتركه فارغًا (جذر المستودع).
   - **المنطقة (Region):** الشرق الأوسط (الإمارات) — الأقرب للمملكة.

### ٢. قاعدة البيانات
من قسم **Database** في إعدادات البيئة: أنشئ قاعدة **Postgres** واربطها بالتطبيق.
تحقن المنصة بيانات الاتصال تلقائيًا، فلا تكتبها يدويًا.

### ٣. متغيرات البيئة (Environment variables)
أضف فقط ما يلي (والباقي تحقنه المنصة):

```
APP_NAME="RRoka ERP"
SESSION_SECURE_COOKIE=true
INITIAL_ADMIN_EMAIL=بريدك
INITIAL_ADMIN_PASSWORD=كلمة مرور قوية من ١٢ حرفًا فأكثر
INITIAL_ADMIN_NAME=اسمك
```

### ٤. أوامر النشر (Deploy Commands)
```
php artisan migrate --force
php artisan rroka:bootstrap-admin
```
الأول يبني قاعدة البيانات أو يحدّثها، والثاني ينشئ حساب المدير في أول نشر فقط (ولا يفعل شيئًا بعد ذلك).
**أوامر البناء (Build Commands):** يكفي السطر `composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader`؛ لا يحتاج النظام إلى npm.

### ٥. النشر
اضغط **Deploy**. عند نجاحه تعطيك المنصة رابطًا للنظام؛ افتحه وتابع قسم "التحقق بعد النشر" أدناه.
ويمكن لاحقًا ربط نطاق خاص (مثل `erp.rroka.sa`) من إعدادات النطاقات في المنصة.

## النشر على منصة أخرى (Docker)

يعمل الملف `Dockerfile` في الجذر على أي منصة تدعم Docker. ما يلزمها:

1. **خادم تطبيق** يبني النظام من هذا المستودع (ملف `Dockerfile` في الجذر).
2. **قاعدة بيانات PostgreSQL 16** مع نسخ احتياطي يومي.
3. **متغيرات البيئة** أدناه.

عند كل تشغيل للصورة، يبني النظام قاعدة البيانات أو يحدّثها تلقائيًا، وينشئ حساب المدير في أول تشغيل فقط (`docker/start.sh`).

## متغيرات البيئة

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `APP_KEY` | يُولَّد مرة واحدة: `php artisan key:generate --show` | **سرّي**؛ تغييره يُبطل الجلسات |
| `APP_URL` | رابط النظام، مثل `https://erp.example.com` | |
| `APP_ENV` / `APP_DEBUG` | `production` / `false` | لا تُفعَّل رسائل التصحيح على الخادم |
| `DB_CONNECTION` | `pgsql` | |
| `DB_HOST` `DB_PORT` `DB_DATABASE` `DB_USERNAME` `DB_PASSWORD` | من مزوّد قاعدة البيانات | يعمل مع الاتصال المباشر أو المجمَّع |
| `SESSION_SECURE_COOKIE` | `true` | جلسات الدخول عبر HTTPS فقط |
| `INITIAL_ADMIN_EMAIL` | بريد مدير النظام | يُستخدم في أول تشغيل فقط |
| `INITIAL_ADMIN_PASSWORD` | كلمة مرور قوية (١٢ حرفًا فأكثر) | **احذفها من الإعدادات بعد أول دخول** |
| `INITIAL_ADMIN_NAME` | اسم المدير | اختياري |
| `DAFTRA_SUBDOMAIN` `DAFTRA_API_KEY` `DAFTRA_TOKEN` | من إعدادات حساب دفترة | اختيارية حتى تفعيل الربط |
| `DAFTRA_ESTIMATE_MAPPING_VERIFIED` | `false` | لا تُغيَّر قبل التحقق من حقول دفترة |

بعد إدخال متغيرات دفترة وإعادة النشر: افتح "الإعدادات ← الربط مع دفترة" واضغط "تشغيل الفحص"، أو نفّذ `php artisan rroka:daftra-probe`.
النتيجة أسماء حقول فقط بلا قيم، وتُرسل للمراجعة قبل بناء التقارير المالية.

### سجل التدقيق والاتصال المجمَّع
كل طلب كتابة يُنفَّذ في معاملة واحدة تحمل هوية المستخدم المنفِّذ محليًا داخلها فقط؛
فلا تنتقل الهوية إلى طلب آخر حتى مع الاتصال المجمَّع (PgBouncer)، وأي طلب يفشل يُلغى كاملًا.

## إذا تعذّر الدخول (استعادة حساب المدير)

**الطريقة الأسهل:** من تبويب الأوامر (Commands) في المنصة نفّذ:
```
php artisan rroka:reset-admin بريدك@example.com
```
يطبع كلمة مرور مؤقتة؛ ادخل بها ثم غيّرها من صفحة المستخدمين.

**طريقة بديلة عبر متغيرات البيئة:**
1. في إعدادات المنصة، ضع في `INITIAL_ADMIN_EMAIL` بريدك، وفي `INITIAL_ADMIN_PASSWORD` كلمة مرور جديدة (١٢ حرفًا فأكثر، بلا علامات تنصيص).
2. أضف متغيرًا جديدًا: `INITIAL_ADMIN_RESET=true`.
3. أعد النشر؛ يعيد أمر `php artisan rroka:bootstrap-admin` تعيين كلمة المرور ويفعّل الحساب.
4. ادخل، ثم **احذف** `INITIAL_ADMIN_RESET` و`INITIAL_ADMIN_PASSWORD` من الإعدادات.

- البريد الإلكتروني لا يتأثر بالأحرف الكبيرة والصغيرة.
- بعد خمس محاولات خاطئة يُوقف الدخول دقيقة واحدة.
- صفحة الفحص `/api/health` تبيّن هل حساب المدير موجود.

## التحقق بعد النشر
1. افتح الرابط؛ يجب أن تظهر شاشة "تسجيل الدخول".
2. ادخل بحساب المدير، ثم **غيّر كلمة المرور** من "المستخدمون".
3. احذف `INITIAL_ADMIN_PASSWORD` من إعدادات المنصة.
4. أنشئ الأدوار والمستخدمين الفعليين من "الأدوار والصلاحيات".
5. أدخل معدلات التكلفة الحقيقية من "معدلات التكلفة".

## ما جرى التحقق منه قبل التسليم
- بُنيت صورة التشغيل (Docker) وشُغّلت على قاعدة بيانات فارغة: أُنشئت الجداول والمدير آليًا، ولم يتكرر إنشاء المدير عند إعادة التشغيل.
- جرى المرور الكامل عبر المتصفح: دخول، عميل، عرض سعر، اعتماد، مشروع، تكلفة، معدلات، أدوار، مستخدم محدود الصلاحية.
- الاختبارات الآلية: ٧٣ اختبارًا لقواعد قاعدة البيانات، و٢٨ اختبارًا للتطبيق.
