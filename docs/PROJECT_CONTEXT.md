# ملخص تنفيذي — مشروع إر روكا للأثاث

> المصدر: ملخص المحادثة التأسيسية كما قدّمه صاحب المشروع (2026-09-26).
> هذا الملف هو المرجع المعتمد للقرارات حتى إضافة الوثائق الأصلية للمستودع.

## السياق
ورشة تصنيع أثاث سعودية مملوكة لأبي موسى، حجم صغير (أقل من 10 مشاريع/شهر).
الهدف: بناء نظام إدارة احترافي للتشغيل.

## القرار المعماري الحاسم (غير قابل للتراجع دون مراجعة رسمية)
**النظام = Operations & Costing فقط** — وليس نظامًا ماليًا مستقلًا:
- يدير: العملاء، المعاينات، عروض الأسعار، المشاريع، BOM، الإنتاج، الجودة، التركيب، التكلفة الفعلية، الربحية.
- **لا يبني** محركًا محاسبيًا أو ضريبيًا داخليًا إطلاقًا.
- يتكامل مع **دفترة (Daftra)** عبر API لكل الفوترة الرسمية، المحاسبة، التحصيل، والامتثال الضريبي (VAT/ZATCA/Zakat).
- يوجد اشتراك دفترة فعلي ونشط.
- **جميع المنتجات Make-to-Order بالكامل** — لا مخزون منتجات تامة، فقط خامات ومستلزمات.

## مبدأ حاكم: Zero Assumption Policy
معدلات التكلفة (أجر ساعة العامل، تكلفة ساعة الآلة، نسبة تحميل المصاريف الصناعية غير المباشرة)
**لا تُقدَّر بمتوسطات صناعية**. الحقول تبقى `NULL` صراحةً (لا صفرًا) لحين إدخال الأرقام الحقيقية
عبر "إعدادات النظام".

## حقائق تقنية موثّقة (docs.daftara.dev)
- Base URL: `https://{subdomain}.daftra.com/api2`
- المصادقة: Header `apikey` + Header `Authorization: Bearer <token>` معًا.
- إنشاء عميل: `POST /clients` — `{"Client": {business_name (إلزامي), ...}}` → 202 مع `id` و`client_number`.
- إنشاء عرض سعر: `POST /estimates` — كائنات `Estimate` + `InvoiceItem[]` → 202 مع `id`.
- تحويل عرض لفاتورة: نقطة API منفصلة، تحتاج فحصًا تفصيليًا قبل التنفيذ.

### قواعد العمل المُطبَّقة في `rroka_schema.sql` (حسب الملخص)
- لا يُنشأ مشروع إلا على عرض سعر بحالة `APPROVED` (Trigger).
- فهرس فريد جزئي: نسخة تصميم واحدة فقط `RELEASED_FOR_PRODUCTION` لكل تصميم.
- لا أمر إنتاج على تصميم غير معتمد للإنتاج (Trigger).
- أرصدة المخزون تتحدث تلقائيًا من كل حركة (Trigger) مع فصل `qty_reserved` عن `qty_issued_total`.
- صُحّح خطأ Forward Reference (`bom_template_lines` → `raw_materials`).

- **السبب:** `rroka_schema.sql` الأصلي غير متاح في المستودع، ولم يُشغَّل على محرك حقيقي أصلًا.
- **القرار (تقني):** بناء مخطط جديد من القواعد الموثقة أعلاه، واختباره فعليًا على PostgreSQL 16.

- **إضافات رقابية لم تكن مذكورة في الملخص:** عرض السعر يُجمَّد بعد الإرسال؛ الإصدار للإنتاج يتطلب موافقة العميل
  على النسخة؛ حركات المخزون غير قابلة للتعديل (تصحيح بحركة عكسية)؛ أمر الإنتاج لا يُغلق دون فحص جودة نهائي ناجح؛
  معدلات التكلفة مؤرَّخة وإلحاقية؛ أي معدل ناقص يجعل التكلفة الإجمالية والربح `NULL` مع بيان الناقص.
- **إن ظهر الملف الأصلي لاحقًا:** يُقارَن بالحالي ويُدمج ما فيه من جداول/حقول غير مغطاة.
