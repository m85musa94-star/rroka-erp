# محرك التكلفة والتسعير — تحليل الوضع الحالي وخطة التنفيذ

> استجابة للبند ٣٤ من مواصفة «ROKA Furniture — Product Costing & Pricing Engine» (2026-10-04).
> هذه وثيقة تحليل وخطة فقط؛ **لم يُعدَّل أي كود أو بيانات**. التنفيذ يبدأ بعد اعتماد القرارات في القسم ٧.

---

## ١. الهيكل الحالي (Architecture)

- Laravel + PostgreSQL. المخطط في ملف واحد `database/schema/rroka_schema.sql` + Migration لكل تعديل على قاعدة الإنتاج القائمة.
- القواعد الرقابية في قاعدة البيانات (Triggers/Constraints) وفي الـ API معًا، وكل رفض برمز `RROKA_*`.
- سجل تدقيق غير قابل للتعديل (`audit_log`) لكل الجداول المهمة.
- القاعدة الحاكمة ١: النظام = تشغيل وتكلفة؛ القيود والضريبة والتحصيل في دفترة.
- القاعدة الحاكمة ٢ (Zero Assumption): أي معدل غير مُدخل = `NULL`، والحساب المعتمد عليه يُعرض «—» مع سبب النقص.

## ٢. ما يوجد اليوم ويمكن إعادة استخدامه

| المواصفة | الموجود حاليًا | الحكم |
|---|---|---|
| المواد + الفئة + الوحدة | `raw_materials` (code, name, category, uom) | يُستخدم كما هو |
| BOM + هالك لكل بند | `design_bom_lines` (quantity, waste_pct)، والكمية المخططة = الكمية × (1 + الهالك) | يطابق معادلة البند ٣؛ يُستخدم للفعلي |
| قوالب BOM | `bom_templates` / `bom_template_lines` | موجودة بلا واجهة؛ تصلح أساسًا لقوالب المنتجات |
| تكلفة المادة الفعلية | `stock_movements` (الصرف بمتوسط التكلفة من فواتير الموردين) | يُستخدم للفعلي |
| أجر ساعة العامل | `worker_rates` (مؤرَّخ، إلحاقي فقط، مع مصدر الرقم) | يُبقى، ويُغذّى من «بطاقة تكلفة الموظف» الجديدة |
| تكلفة ساعة الآلة | `machine_rates` (مؤرَّخ، إلحاقي فقط) | يُبقى، ويُغذّى من «بطاقة تكلفة الآلة» الجديدة |
| مكونات راتب الموظف | `employee_contracts` (أساسي، سكن، نقل، أخرى، ساعات أسبوعية) | مصدر مقترح لبطاقة التكلفة؛ ينقصه التأمينات والإقامة |
| ساعات العمل الفعلية | `labor_logs`, `machine_logs`, `installation_workers` | تُستخدم؛ ينقصها مركز التكلفة والعملية |
| الحضور | `attendances` (ساعات الحضور) | يفرّق بين ساعات الحضور والساعات الإنتاجية |
| المصروف المباشر على المشروع | `expenses.project_id` → `direct_expense_cost` | يُستخدم كما هو |
| مصروفات غير مباشرة فعلية | `expense_categories.is_overhead` | تغذي «المصروف غير المباشر الفعلي» للمقارنة |
| التكلفة الفعلية للمشروع | `v_project_actual_cost` (مواد، عمالة، آلات، مصروفات مباشرة، تحميل غير مباشر) | يُعاد بناؤها لتستخدم معدلات مراكز التكلفة |
| تحميل غير المباشر | `overhead_rates`: نسبة واحدة عامة من العمالة أو التكلفة الأولية | **لا يطابق المواصفة** (البند ١١) ← يُستبدل بمعدلات لكل مركز تكلفة |
| عرض السعر | `quotations` + `quotation_lines` (وصف حر، كمية، سعر) | ينقصه المنتج والتكلفة المعيارية والتسعير |
| المشروع | `projects` (قيمة العقد من العرض المعتمد) | ينقصه حالة «مغلق» وأوامر التغيير |
| العهد والتحويلات | `payment_accounts`, `treasury_transfers` | يحقق البند ٢٨ جزئيًا: التحويل والعهدة ليسا مصروفًا حتى التسوية |

## ٣. الفجوات: جداول وحقول جديدة مطلوبة

**أ. البيانات الأساسية والمعدلات (كلها مؤرَّخة، إلحاقية، بإصدار ومصدر ومُدخِل ومعتمِد):**
1. `cost_centers` — النجارة، الماكينات، التنجيد، الدهان، التجميع، التركيب، خدمات الإنتاج (قابلة للإضافة؛ **لا تُنشأ تلقائيًا** إلا بموافقتك).
2. `employee_cost_cards` — مكونات التكلفة الشهرية (أساسي، سكن، نقل، تأمينات، إقامة ورسوم حكومية، بدلات، أخرى)، والطاقة النظرية والعملية بالساعات، وأسباب الاستبعاد ← أجر الساعة الإنتاجية. عند الاعتماد يُكتب صف في `worker_rates`.
3. `employee_cost_center_shares` — توزيع ساعات الموظف على أكثر من مركز تكلفة (النسب مجموعها 100%).
4. `machine_cost_cards` — تكلفة الشراء، العمر، القيمة المتبقية، الساعات السنوية العملية، القدرة kW، معامل التحميل، الصيانة، قطع الغيار، أخرى ← معدل ساعة الآلة بتفصيله. عند الاعتماد يُكتب صف في `machine_rates`. ويُضاف `machines.cost_center_id`.
5. `energy_rates` — سعر الكيلوواط ساعة (مؤرَّخ).
6. `overhead_pools` + `overhead_pool_lines` — لكل مركز تكلفة ولكل فترة: بنود التكلفة غير المباشرة المتوقعة، ومحرك التكلفة (ساعات عمل / ساعات آلة)، والطاقة العملية للمحرك ← معدل التحميل لكل ساعة.
7. `period_allocations` — نسبة المصاريف البيعية والإدارية للتكلفة الكاملة (Fully Loaded) بأساس محدد.
8. `pricing_settings` — هامش مستهدف افتراضي، حد أدنى للهامش، نسبة الضريبة للعرض فقط، طريقة التسعير الافتراضية (هامش أو Markup).
9. `material_standard_prices` — السعر المعياري لكل مادة (مؤرَّخ)، يُقترح من آخر سعر شراء أو متوسط التكلفة **ولا يُفترض**.
10. هالك افتراضي حسب **المادة أو فئة المادة** (`waste_defaults`)، ويُعدَّل لكل بند.

**ب. التكلفة المعيارية والتسعير قبل التصنيع:**
11. `product_templates` (اختياري) — منتج نموذجي بفئة وBOM وRouting جاهزة للنسخ.
12. `cost_estimates` — تقدير تكلفة لكل بند عرض سعر (المنتج، المقاسات، الكمية، الخامة، القماش، الخشب، الإسفنج…).
13. `cost_estimate_materials` — BOM التقدير: الكمية، الهالك، الكمية المعدّلة، السعر المعياري، الإجمالي.
14. `cost_estimate_operations` — Routing: العملية، مركز التكلفة، ساعات العمل، ساعات الآلة، ساعات التجهيز (مرة للدفعة)، المعدل، التكلفة.
15. `cost_estimate_direct_costs` — تصنيع خارجي، مقاول باطن، توصيل خاص، تركيب، رافعة، دهان خارجي، تصميم، عمولة… (لكل وحدة أو مرة واحدة).
16. `cost_estimate_snapshots` — صورة مجمّدة عند اعتماد العرض: كل رقم، ومعه المعدل المستخدم ورقم إصداره ومصدره.

**ج. الفعلي والانحرافات:**
17. حقول جديدة: `labor_logs.cost_center_id` و`operation`، و`machine_logs.operation`.
18. ربط المنتج بالإنتاج: `designs.quotation_line_id`، ليُحسب الفعلي لكل منتج لا لكل مشروع فقط.
19. `change_orders` — وصف التعديل، مواد وساعات إضافية، تكلفة وسعر إضافيان، موافقة العميل وتاريخها؛ تُفصل عن انحراف الإنتاج.
20. حالة `CLOSED` للمشروع: تُجمَّد التكلفة الفعلية بعد الإقفال، ولا تغيير إلا بمراجعة مسجّلة.
21. Views: ورقة تكلفة المنتج، المعياري مقابل الفعلي، الانحرافات، أداء مراكز التكلفة، كفاءة العمالة، استغلال الآلات، تحليل الهامش.

## ٤. المعادلات كما ستُنفَّذ (كلها مختبرة آليًا)

| البند | المعادلة |
|---|---|
| كمية المادة | الكمية المعدّلة = الكمية × (1 + الهالك%) |
| تكلفة المادة | الكمية المعدّلة × السعر المعياري |
| تكلفة الموظف | مجموع المكونات الشهرية |
| أجر الساعة | التكلفة الشهرية ÷ الساعات الإنتاجية العملية (مع حفظ النظرية والفعلية) |
| إهلاك الآلة/ساعة | (الشراء − المتبقية) ÷ العمر ÷ الساعات السنوية العملية |
| كهرباء الآلة/ساعة | kW × معامل التحميل × سعر الكيلوواط ساعة |
| معدل ساعة الآلة | إهلاك + كهرباء + صيانة + قطع غيار + أخرى (كلها للساعة) |
| معدل التحميل | التكلفة غير المباشرة المتوقعة للمركز ÷ الطاقة العملية لمحركه |
| التحميل على المنتج | استخدام المنتج للمحرك × معدل التحميل |
| تكلفة التصنيع | مواد + عمالة + آلات + مصروفات مباشرة + تحميل غير مباشر |
| الدفعة | (تكلفة الوحدة المتغيرة × الكمية) + التجهيز + التكاليف لمرة واحدة |
| التكلفة الكاملة | تكلفة التصنيع + حصة المصاريف البيعية والإدارية |
| سعر بالهامش | التكلفة ÷ (1 − الهامش%) |
| سعر بـ Markup | التكلفة × (1 + Markup%) |
| الخصم | يُخفّض السعر لا التكلفة؛ ثم يُعاد حساب الربح والهامش، مع تحذير إن كُسر الحد الأدنى |
| الضريبة (للعرض فقط) | السعر قبل الضريبة × النسبة المُعدّة؛ لا تدخل الإيراد ولا الربح |
| الانحراف | الفعلي − المعياري، والنسبة ÷ المعياري؛ مع تفصيل: سعر المادة، كميتها، أجر العمالة، كفاءتها، الآلات، التحميل، التركيب والتوصيل |

**منع الازدواجية (البند ٢٨):**
- كهرباء الآلات المحمّلة في معدل الآلة تُطرح تلقائيًا من بند الكهرباء العامة في وعاء التحميل.
- راتب موظف مُسجَّل كعمالة مباشرة لا يُقبل في وعاء العمالة غير المباشرة عن الفترة نفسها.
- المصروف المرتبط بمشروع لا يدخل وعاء التحميل.
- التحويلات وصرف العهد ليست مصروفًا حتى تسويتها بإيصالات (مطبَّق حاليًا).

## ٥. أثر التغيير على الوحدات الحالية

| الوحدة | الأثر |
|---|---|
| عروض الأسعار | يُضاف تقدير تكلفة وتسعير لكل بند. السعر الذي يكتبه المستخدم يبقى سعره، والنظام **يحذّر ولا يغيّر بصمت**. يُجمَّد التقدير عند الاعتماد. العروض الحالية تبقى كما هي بلا تقدير. |
| المشاريع | التكلفة الفعلية تُحمَّل بمعدلات مراكز التكلفة بدل النسبة العامة. تُضاف حالة «مغلق» وأوامر التغيير. المشاريع القائمة تبقى على طريقتها القديمة إن وُجدت لها نسبة عامة. |
| الموظفون | بطاقة تكلفة لكل موظف إنتاج. مكونات الراتب تُرى فقط بصلاحية العقود أو معدلات التكلفة، وأجر الساعة بصلاحية التكلفة. |
| المخزون | سعر معياري مؤرَّخ لكل مادة وهالك افتراضي حسب الفئة. حركات المخزون لا تتغير. |
| المشتريات | لا تغيير؛ تبقى مصدر التكلفة الفعلية للمواد واقتراح السعر المعياري. |
| المصروفات والخزينة | لا تغيير في المستندات. المصروفات غير المباشرة الفعلية تُقارن بالتحميل المعياري (انحراف التحميل). |
| المحاسبة (دفترة) | **لا قيود ولا ترحيل.** الإيراد = قيمة العقد + أوامر التغيير المعتمدة، حتى يُتحقق من قراءة الفواتير من دفترة. |

## ٦. خطة التنفيذ والترحيل (Migration Plan)

كل مرحلة: تعديل في `rroka_schema.sql` + Migration آمنة (`IF NOT EXISTS`) + اختبارات قواعد (مسموح وممنوع) + اختبارات معادلات + ترجمة + واجهة على نمط Odoo. **لا حذف ولا تعديل لبيانات قائمة.**

**المرحلة ١ — المعدلات والبيانات الأساسية**
مراكز التكلفة؛ بطاقات تكلفة الموظفين (مع الطاقة النظرية والعملية)؛ بطاقات تكلفة الآلات؛ سعر الكهرباء؛ أوعية التحميل لكل مركز؛ نسبة المصاريف البيعية والإدارية؛ إعدادات التسعير؛ الأسعار المعيارية للمواد والهالك الافتراضي. كل معدل له: من/إلى، المصدر، المُدخِل، المعتمِد، تاريخ الاعتماد، الإصدار.
*الاختبارات:* أجر الساعة، معدل الآلة، الكهرباء، معدل التحميل، منع ازدواج الكهرباء، المعدل لا يُستخدم قبل اعتماده.

**المرحلة ٢ — التكلفة المعيارية والتسعير في عرض السعر**
تقدير لكل بند عرض (BOM + Routing + تكاليف مباشرة + كمية وتجهيز)، وورقة تكلفة (مباشرة، تصنيع، كاملة)، والتسعير (هامش أو Markup، خصم، ضريبة للعرض)، والتحذيرات، والتجميد عند الاعتماد مع نسخة المعدلات المستخدمة. قوالب منتجات اختيارية.
*الاختبارات:* BOM، الهالك، المعياري، الكامل، الهامش، Markup، الخصم، الضريبة، التجهيز للدفعة، ثبات العرض التاريخي بعد تغيير المعدلات.

**المرحلة ٣ — الفعلي والانحرافات والتقارير**
وسم ساعات العمل بمركز التكلفة والعملية، وربط التصميم ببند العرض، والتحميل الفعلي بالمحركات، وأوامر التغيير، وإقفال المشروع، وتقارير الانحراف (البند ٢٠) والتقارير السبعة (البند ٣١).
*الاختبارات:* انحرافات المواد والعمالة والآلات والتحميل، وفصل أمر التغيير عن انحراف الإنتاج.

## ٧. قرارات مطلوبة منك قبل البدء

1. **الضريبة في التسعير:** القاعدة ١ تمنع احتساب الضريبة هنا. المقترح: تُعرض الضريبة **للعلم فقط** في شاشة التسعير بنسبة تُدخلها أنت، ولا تُرحَّل، والضريبة الرسمية تبقى من دفترة. هل توافق على هذا التفسير؟
2. **إلزامية التقدير:** هل يُمنع اعتماد عرض سعر **جديد** بلا تقدير تكلفة مكتمل؟ (المقترح: نعم، للعروض المُنشأة بعد التفعيل فقط).
3. **النسبة العامة القديمة للتحميل:** تُستبدل بمعدلات مراكز التكلفة للمشاريع الجديدة، وتبقى للمشاريع القائمة. موافق؟
4. **مراكز التكلفة السبعة:** هل أُنشئها كما في المواصفة، أم تُدخلها أنت؟
5. **اعتماد المعدلات:** الفريق صغير؛ المقترح أن يُسمح بالاعتماد الذاتي مع تعليمه للمراجعة، كما في المشتريات. موافق؟
6. **ترتيب التنفيذ:** البدء بالمرحلة ١.

## ٨. ما لن يفعله النظام (التزامًا بالمواصفة والقواعد)

- لا يوزّع أي تكلفة بالتساوي على عدد المنتجات.
- لا يملأ أي معدل أو ساعة أو سعر أو هالك أو طاقة برقم افتراضي؛ النقص يُعرض «يتطلب إدخالًا».
- لا يغيّر تكلفة عرض معتمد عند تعديل المعدلات لاحقًا.
- لا يُنشئ قيودًا محاسبية ولا يحسب ضريبة رسمية.
